# Readiz 웹앱 Android

한국어로 작업 결과를 설명한다. 앱 생성·갱신·배포 중 요청된 범위를 수행한다.

## 시작

새 앱은 [commands.md](references/commands.md)의 생성기로 만든다. 서명키 생성·기존 키 연결·백업·복원은 [signing.md](references/signing.md)를 읽는다. 템플릿을 복사한 뒤 값들을 수작업으로 찾아 바꾸지 않는다. 생성기와 원본 템플릿은 이 스킬 안에 함께 포함되어 있다.

## 앱 생성과 기존 앱 구분

기존 앱은 applicationId, 서명 인증서, WebView의 웹 origin과 저장소 사용 방식을 먼저 확인한다. 업데이트를 위해 앱을 삭제하거나 키를 다시 생성하지 않는다. 누락된 기존 키는 원래 키를 복원해야 한다. 새로운 앱의 이름·패키지·시작 URL·허용 탐색 경로·업데이트 URL·아이콘은 앱 설정으로 분리한다. WebView와 TWA는 인증 및 브라우저 저장소가 다르므로 기존 방식의 전환을 단순 템플릿 적용으로 처리하지 않는다.

WebView는 HTTPS origin과 경로 경계를 기준으로 내부 탐색을 제한한다. 인증 이동은 실제 서비스 흐름에 필요한 경로만 포함한다. 외부 링크는 사용자의 클릭에 한해 외부 브라우저로 연다. JavaScript bridge, 파일 접근, 혼합 콘텐츠, SSL 오류 무시는 기본 템플릿에 추가하지 않는다.

## 업데이트

웹 콘텐츠 배포와 네이티브 APK 업데이트를 분리한다. 앱 진입·복귀 시 확인하고 다운로드하는 기본 구현과 앱이 종료된 동안의 백그라운드 작업을 혼동하지 않는다. 기본 설치 방식은 Android 확인 화면을 거친다. 무인 설치가 요청되면 별도 요구사항·지원 조건으로 검토하며 자동 다운로드 요구만으로 추가하지 않는다.

APK 메타데이터, 파일 검증, 게시 순서와 롤백은 [release.md](references/release.md)를 따른다. 서명키·비밀번호·APK·런타임 상태는 저장소 밖에 둔다. 생성과 빌드는 운영 배포를 자동 실행하지 않는다.

## 검증과 인계

새 앱 생성기는 다른 패키지명·URL로 생성한 결과를 실제 컴파일해 하드코딩 누출을 확인한다. 기존 앱 갱신은 기존 서명 일치와 증가한 versionCode를 확인한다. 관련 네비게이션·업데이트 상태·실패 경로 검사를 실행한다. 배포가 요청되었으면 실제 버전 메타데이터와 APK 바이트·해시, 공개 설치 페이지를 확인한다.

빌드·서버·브라우저·물리 기기 확인을 각각 기록한다. 물리 기기 설치나 실계정 검증을 생략하라는 사용자의 지시가 있으면 그 경계를 유지한다. 테스트 때문에 열린 탭·서버만 정리하고, 커밋과 배포 완료를 구분해 보고한다. 기존 앱에 업데이터가 없던 경우 이번 APK 한 번은 덮어 설치해야 함을 알린다.
