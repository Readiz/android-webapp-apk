# APK 업데이트 계약

기본 업데이터는 웹페이지 로딩·로그인 완료와 독립적으로 앱 실행·복귀마다 확인한다. 이미 진행 중인 확인·다운로드만 합친다. 권한 거절·나중에·설치 취소는 해당 versionCode의 안내만 24시간 미루고, 더 높은 버전의 확인·다운로드를 막지 않는다. 네트워크·설치 준비 실패는 다음 복귀에 재시도한다.

메타데이터는 packageName, versionCode, versionName, size, sha256만 반환한다. 서버의 경로나 임의 다운로드 URL, 인증값을 담지 않는다. Android는 설정된 HTTPS 업데이트 서버에서 버전과 SHA-256으로 고정한 APK를 받는다. 인증 쿠키를 업데이트 요청에 복사하지 않는다.

AOA에서 검증한 기본 상한은 메타데이터 4 KiB, APK 16 MiB다. 더 큰 앱은 실제 APK 크기와 저장 공간을 확인한 뒤 클라이언트·서버 양쪽을 일치시킨다. 접속·읽기·전체 다운로드 제한 시간을 두고 리다이렉트를 자동 추적하지 않는다. 서버는 버전 문자열·크기·해시를 검증하고, 같은 버전 파일의 바이트와 메타데이터가 맞지 않으면 업데이트를 제공하지 않는다.

다운로드는 앱 전용 캐시의 임시 파일에 저장한다. 설치 전에 크기·SHA-256·패키지·정확한 버전·기존 앱과 같은 서명 인증서를 검증한다. 현재 이하 versionCode는 설치하지 않는다. 앱이 배경으로 간 동안에는 설치 UI를 띄우지 않는다. 설치 허용 설정 복귀·취소·오프라인·중단 다운로드를 다루고, 거절 직후 반복해서 권한 창을 열지 않는다. 설치 결과 수신기는 비공개이며 저장한 세션 ID를 확인한다.

배포는 서명된 버전 APK와 그 메타데이터를 먼저 저장·검증하고, 마지막에 최신 메타데이터를 같은 파일시스템에서 원자적으로 전환한다. 기존 버전 고정 다운로드는 유지한다. 같은 버전 파일을 다른 바이트로 덮어쓰지 않는다. 빌드는 외부 출력 디렉터리에만 산출물을 만들며, 배포는 별도 명령으로 실행한다.

서버 최신 포인터를 이전 버전으로 돌리면 새 설치 제공을 되돌릴 수 있지만, 이미 설치된 높은 versionCode가 내려가지는 않는다. 기기 쪽 수정 배포는 수정된 코드에 더 높은 versionCode를 부여한다.
